A tracked project · the work

Every tracked project is born with the same parts and kept in the same order: by machine where it can be, by rule where it cannot.

A project is one row in the registry and a home for its tickets. From there it grows in a fixed order: rules, words and lessons at birth, every piece of work a named ticket with a check, design in design/, nothing durable until it is pushed. Each step says what holds it.

Tickets · the work

A ticket is one thing to finish, carrying the evidence that would prove it finished.

One markdown file per ticket, in each project's own git home. Its name is a readable sentence, never a number, claimed by an atomic push so two machines cannot take the same one. Every ticket carries an outcome check or a named gap.

Bearing · intake

Every ten minutes, Bearing reads everything Lukas can read and files what matters.

A scheduled sweep of mail, calendar, chat and meeting recordings, almost all deterministic Python. The few model calls are isolated, toolless, one per batch and cached, so a hostile message can reach only its own batch.

Automation · intake

A rule approved once is applied for him afterwards, and it always says what it did.

Standing decisions: merge a duplicate, drop an observation, hide someone else's task. A new rule starts unapproved and in dry run. Every pass prints an AUTOMATION: line, and any decision can be undone.

Reconcile · truth

Nothing reminds him about work that is already provably done.

Before any reminder is composed, every store's outcome checks run. Only a SATISFIED check closes an item; a resolver never guesses a drop. A separate read-only report lists stored state that disagrees with reality.

  1. ✓ticket · fix the sweep flagcheck: commit reached the remote → SATISFIED, closed as done
  2. ○obligation · send the slidescheck: reply in Sent → not yet, stays open
  3. —beacon · grant report duegap: no mechanical check exists, named as such

Handoff and wake · the work

A session's judgment outlives its context, and the next session must answer it.

Before it ends, a session writes pointers in one strict shape, each with an imperative NEXT:. Nothing counts as saved until it is pushed. The next session's first turn wakes and answers every pointer.

`LODESTAR_TRY_FIRST_RUN_DEMO` — passes on a clean clone; NEXT: run it as a second identity✓ committed and pushed · HANDOFF READY — a new session opens in the same repo —1 open pointer → answered before other work

Instructions across machines · the fleet

Edit a rule once, and every machine runs by it after its next sweep.

Plain code renders the shared rules, settings and skill links on every machine. What code cannot judge, an agent does as a ritual: wake, crystallize, hand off.

Guard rails

  • Source waits for an author. The sweep auto-commits only quiet, non-source files.
  • A hand edit is captured, never overwritten, and reaches no other machine until adopted.
  • Fast-forward only. A conflict aborts and flags. A flagged Lodestar row means nothing from that machine is reaching the fleet.

$ sync.py · hourly on each machine $ claudeconf.py check

The Sweep · the fleet

Every hour, each machine quietly gets its state to the others, and never forces.

Fast-forward, commit only work that has gone quiet, push. A conflict aborts and raises a flag instead of merging by hand. Heavy work in a repo can pause the sweep there for a few hours.

$ sync.py --pause 8h --reason "big refactor"

Fleet configuration · the fleet

One table decides which skills and settings every machine gets.

The global instructions are rendered from sections; settings, status line and skill links converge per machine. A live file is rewritten only when provenance proves nothing is lost; otherwise it is captured verbatim.

Tender · the fleet

A signed directive can travel between his machines, and the target checks the signature before it acts.

Propose a named recipe for another machine, sign it, and git carries it as a durable mailbox. A session may sign the recipe tier; the shell and release tiers need the owner key's passphrase, typed at a terminal.

$ tender.py propose --target desktop --recipe run-rewrite-recover

The prose guard · truth

Private work text can never reach a public history.

Ticket prose, journal notes and obligations live in a separate repository on a private host. Pre-commit and pre-push hooks refuse any private text bound for the public remote, and a fix command moves it where it belongs.

Attribution · measure

Spend is joined to the ticket it served, so cost per result can be read.

Because every session names its ticket, a deterministic pass can attribute each model message to that ticket. Figures are read in weighted tokens, so different models compare directly; a session that never names a ticket shows up as unattributed.
